**评估日期**: 2026-06-23

**LRC 版本**: v0.5.6

**评估合规**: BEIR 标准协议 + LongMemEval 标准协议 + 公平性原则

**报告性质**: 6 次基准测试汇总对比

---

## 1. 评估概述

### 1.1 评估背景

LRC（Loong Recall）是**记忆检索系统**（注入 + 召回 + 排序），不是 RAG 问答系统。为客观评估 LRC 的检索基本功，我们在 6 个标准基准测试上进行了全面评估，覆盖关键词检索、自然语言问题、多跳推理、金融领域问题、长时记忆能力和综合记忆能力。

### 1.2 公平性原则

本次评估严格遵守以下公平性原则：

- **不利用 ground truth**: 所有文档 `importance=5`（统一），不利用答案信息差异化
- **使用标准指标**: BEIR 标准指标（MRR@10, Recall@10, Hit Rate@10）+ LongMemEval 标准指标
- **蓄水池抽样随机文档**: 不偏向相关文档
- **跳过合成记忆**: 避免 synthesis 类型干扰评估
- **不修改 LRC 源代码**: 使用原版 release 二进制
- **公平性改革**: LRC 原生基准从"测架构"转变为"测能力"

### 4.3 deep 模式说明

v3-deep 模式（洛书几何 + 八卦预过滤）在 LongMemEval 上 5 实例全 ✗（0% 召回）。原因：
- 八卦预过滤将查询编码为 8 维向量后投影到八卦分类，只保留同卦或相邻卦的记忆
- LongMemEval 的问题和答案内容可能被分到不同八卦，导致预过滤阶段直接排除正确答案
- deep 模式是为结构化知识检索设计（如代码库搜索），而非自然语言对话的关键词匹配
- 这不代表 LRC 的洛书几何编码"无用"，只是不在这个基准测试的适用范围内

## 5. LRC 检索能力综合分析

### 5.1 TF-IDF 检索引擎

**综合评估**: LRC 的 TF-IDF 检索引擎在多种场景下表现优秀。

| 场景 | 表现 | 关键指标 |
| :--- | :--- | :--- |
| 关键词检索（MS MARCO） | 优秀 | MRR@10=0.7749, Recall@10=0.9250 |
| 实体名匹配（HotpotQA） | 优秀 | MRR@10=0.7964, Hit Rate@10=0.9500 |
| 长时记忆（LongMemEval） | 优秀 | Session Recall@10=85.74% |
| 自然语言问题（NQ） | 一般 | MRR@10=0.5389 |
| 金融领域（FiQA） | 较弱 | MRR@10=0.2729 |
| 综合能力（LRC 原生） | 卓越 | 11/11 PASS, 总评分 0.94 |

**优势**:
- 检索速度极快（13-21ms/查询，LongMemEval 2.6ms/查询）
- 词边界检测避免了子串误匹配
- Session + Turn 双层索引充分利用会话结构
- 在关键词和实体名匹配场景下表现优秀

**局限**:
- 对自然语言问题和金融领域问题的词汇匹配能力有限
- 依赖词汇重叠，无法处理语义相似但词汇不重叠的查询

### 5.2 LLM 查询翻译器

**综合评估**: LLM 查询翻译器是 LRC 的核心能力之一，在 BEIR 数据集上效果显著。

| 场景 | LLM 增益 | 关键表现 |
| :--- | :--- | :--- |
| 金融领域（FiQA） | **+63.2%** | 增益最大，专业术语翻译有效 |
| 自然语言问题（NQ） | +48.7% | 增益显著，桥接语义鸿沟 |
| 多跳推理（HotpotQA） | +17.8% | 增益中等，Hit Rate 达 100% |
| 关键词查询（MS MARCO） | +14.8% | 增益最小，关键词已高度重叠 |
| LongMemEval knowledge-update | +14.10% | 端到端准确率提升最显著 |
| LongMemEval multi-session | -6.76% | 出现回退，关键词过于泛化 |

**工作原理**: LLM 将自然语言问题翻译为答案可能包含的关键词，桥接"问题词与答案词不重叠"的语义鸿沟。

**优势**:
- 在词汇匹配困难的场景下（FiQA, NQ）增益最显著
- 能将多跳问题翻译为多个答案关键词
- 在 BEIR 数据集上全面提升检索精度

**局限**:
- 在多会话场景下可能产生过于泛化的关键词，引入噪声
- 增加检索延迟（从毫秒级到秒级）
- 依赖 LLM API 可用性

### 5.3 洛书几何编码

**综合评估**: 洛书几何编码在结构化知识检索场景下有辅助作用，但不适合自然语言对话的关键词匹配任务。

| 场景 | 表现 | 说明 |
| :--- | :--- | :--- |
| BEIR 数据集 | ★★★☆☆ | 自动编码+加权，辅助检索 |
| LRC 原生基准 | ★★★☆☆ | 自动编码+加权，辅助检索 |
| LongMemEval | ★☆☆☆☆ | 八卦预过滤与关键词匹配不兼容 |

**设计意图**: deep 模式是为结构化知识检索设计（如代码库搜索、文档检索），而非自然语言对话的关键词匹配。

### 5.4 性能特征

| 场景 | TF-IDF 延迟 | LLM 延迟 | 评级 |
| :--- | :--- | :--- | :--- |
| MS MARCO | 0.013s | 1.203s | ★★★★★ |
| NQ | 0.018s | 1.084s | ★★★★★ |
| HotpotQA | 0.021s | 1.047s | ★★★★★ |
| FiQA | 0.019s | 1.293s | ★★★★★ |
| LongMemEval | 0.0026s | ~0.75s | ★★★★★ |

**结论**: TF-IDF 模式延迟极快（<25ms），满足实时需求；LLM 模式延迟可接受（~1s），适合对精度要求高的场景。

## 6. LRC 检索能力综合评级

### 6.1 v0.5.6 综合评级

| 能力 | 评级 | 关键指标 | 说明 |
| :--- | :--- | :--- | :--- |
| TF-IDF 检索 | ★★★★☆ | MRR 0.27-0.80, Recall 85.74% | 关键词/实体名匹配优秀，自然语言/金融领域较弱 |
| LLM 查询翻译 | ★★★★☆ | 增益 +14.8% ~ +63.2% | BEIR 数据集核心能力，LongMemEval 效果分化 |
| 洛书几何编码 | ★★★☆☆ | 自动编码+加权 | 结构化知识检索辅助，不适合自然语言对话 |
| 检索延迟 | ★★★★★ | 2.6ms ~ 21ms | TF-IDF 极快，满足实时需求 |
| 大规模支持 | ★★★★★ | 500 文档/470 实例 | v0.5.6 修复后支持高效检索 |
| 综合记忆能力 | ★★★★★ | 11/11 PASS | LRC 原生基准公平版全通过 |

### 6.2 核心发现

1. **TF-IDF 检索基本功扎实**: 在关键词检索（MS MARCO）、实体名匹配（HotpotQA）、长时记忆（LongMemEval）场景下表现优秀，MRR 0.77-0.80，Session Recall 85.74%

2. **LLM 查询翻译器是核心能力**: 在 BEIR 数据集上全面提升检索精度，增益 +14.8% ~ +63.2%，在词汇匹配困难的场景下效果最显著

3. **公平性验证通过**: LongMemEval v3（公平）Session Recall@10=85.74%，证明了 LRC 在不利用 ground truth 的条件下的真实基本功

4. **v0.5.6 修复效果显著**: 写回性能瓶颈解决，500 文档场景下 TF-IDF 平均检索仅 13-21ms，LongMemEval 470 实例评估 < 60 秒

5. **LLM 增益与查询类型强相关**: FiQA（金融专业）> NQ（自然语言）> HotpotQA（多跳）> MS MARCO（关键词）

6. **deep 模式适用范围有限**: 洛书几何编码的八卦预过滤机制与关键词匹配任务不兼容，适合结构化知识检索

7. **LRC 原生基准公平版全通过**: 11/11 PASS，总评分 0.94，证明了 LRC 的综合记忆能力

## 7. 使用建议

### 7.1 场景推荐

| 场景 | 推荐模式 | 理由 |
| :--- | :--- | :--- |
| 关键词检索（< 25ms 响应） | TF-IDF | 13-21ms 平均延迟，满足实时需求 |
| 自然语言问题（精度优先） | TF-IDF + LLM | LLM 翻译器在 NQ 场景下效果显著（+48.7%） |
| 多跳推理问题 | TF-IDF + LLM | LLM 翻译器提升 Recall@10 从 0.7550 到 0.9500 |
| 金融领域问题 | TF-IDF + LLM | LLM 翻译器提升 MRR@10 从 0.2729 到 0.4453（+63.2%） |
| 长时记忆（单会话信息抽取） | TF-IDF | 87-98% 准确率，2.6ms 延迟 |
| 长时记忆（知识更新追踪） | TF-IDF + LLM | LLM 翻译器提升 +14.10% |
| 大规模记忆库（> 1000 条） | TF-IDF | 修复一已解决 O(N²) 瓶颈 |
| 结构化知识检索 | deep 模式 | 洛书几何编码适用场景 |

### 7.2 数据集适配建议

| 数据集类型 | 文档内容格式 | 推荐模式 |
| :--- | :--- | :--- |
| 有标题的文档（如 Wikipedia） | title + text | TF-IDF 或 LLM |
| 无标题的文档（如 Web 段落） | text only | TF-IDF 或 LLM |
| 自然语言查询 | - | LLM（效果显著） |
| 关键词查询 | - | TF-IDF（已足够） |
| 金融领域查询 | - | LLM（增益最大） |
| 多会话场景 | Session + Turn 双层 | TF-IDF（LLM 可能引入噪声） |

| TF-IDF 检索 | 优秀 | 在关键词/实体名/长时记忆场景下表现优秀，自然语言/金融领域较弱 |
| LLM 查询翻译器 | 卓越 | BEIR 数据集核心能力，增益 +14.8% ~ +63.2% |
| 洛书几何编码 | 良好 | 结构化知识检索辅助，不适合自然语言对话 |

| 大规模支持 | 优秀 | v0.5.6 修复后支持 500+ 文档高效检索 |
| 综合记忆能力 | 卓越 | LRC 原生基准公平版 11/11 PASS |

### 9.2 公平性验证

本次评估严格遵守公平性原则：
- **BEIR 数据集**: 所有文档 importance=5（统一），不利用 ground truth
- **LongMemEval**: v3 公平版不利用 has_answer 差异化，统一 importance=5
- **LRC 原生基准**: 公平性改革从"测架构"转变为"测能力"

**结论**: LRC v0.5.6 在公平条件下的检索基本功扎实，TF-IDF 检索 + LLM 查询翻译器的组合在多种场景下表现优秀，证明了 LRC 作为记忆检索系统的核心价值。

### 9.3 改进方向

1. **TF-IDF 检索**: 提升自然语言问题和金融领域问题的词汇匹配能力
2. **LLM 查询翻译器**: 优化多会话场景的翻译 prompt，避免关键词过于泛化
3. **洛书几何编码**: 探索在自然语言对话场景下的适用性
4. **deep 模式**: 优化八卦预过滤机制，避免排除正确答案
5. **时序推理和偏好推理**: 搭配更强的 LLM 推理模型
