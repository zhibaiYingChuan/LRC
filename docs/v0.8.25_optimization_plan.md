## 2. 修复项详细方案

### 2.1 P0：AI 工具检测逻辑修复

**问题**：
1. Trae CN 被误检测为 Trae：TraeCNDetector 的 detect 逻辑存在缺陷，导致 Trae CN 被识别为 Trae
2. CodeBuddy 未检测到：CodeBuddy 的 binary_paths 为空数组，仅依赖 exe_names 全盘扫描，但扫描逻辑可能未覆盖最新安装路径

**根因分析**：
- `TraeCNDetector::detect()` 优先检测 `%LOCALAPPDATA%/Programs/Trae CN/Trae CN.exe` 路径，但回退逻辑可能落入 TraeDetector 的检测范围
- CodeBuddy 的 `binary_paths: &[]` 导致 DotDirDetector 无法通过路径检测确认安装，仅依赖 `exe_names` 全盘扫描，但全盘扫描可能在时间窗口内未命中

**修复方案**（3 个子任务）：

#### 2.1.1 桌面快捷方式扫描（新增）

**目标**：通过扫描 `%USERPROFILE%/Desktop/*.lnk` 和公共桌面 `%PUBLIC%/Desktop/*.lnk` 快捷方式检测 AI 工具

**实现方案**：
```rust
/// 扫描桌面快捷方式，返回匹配的工具 ID 列表
fn scan_desktop_shortcuts() -> Vec<String> {
    let mut found = Vec::new();
    let desktop_dirs = [
        // 当前用户桌面
        PathBuf::from(std::env::var("USERPROFILE").unwrap_or_default()).join("Desktop"),
        // 公共桌面
        PathBuf::from(std::env::var("PUBLIC").unwrap_or_default()).join("Desktop"),
        // 备用：OneDrive 同步桌面
        PathBuf::from(std::env::var("USERPROFILE").unwrap_or_default()).join("OneDrive/Desktop"),
    ];
    
    for dir in &desktop_dirs {
        if !dir.exists() { continue; }
        if let Ok(entries) = std::fs::read_dir(dir) {
            for entry in entries.flatten() {
                let path = entry.path();
                if path.extension().and_then(|e| e.to_str()) != Some("lnk") {
                    continue;
                }
                let name = path.file_stem()
                    .and_then(|n| n.to_str())
                    .unwrap_or("")
                    .to_lowercase();
                // 匹配已知工具名称
                for tool in KNOWN_TOOLS {
                    if name.contains(&tool.name.to_lowercase()) {
                        found.push(tool.id.to_string());
                    }
                }
            }
        }
    }
    found
}
```

**关键逻辑**：
- 读取 `.lnk` 快捷方式的目标文件名（而非快捷方式名称）
- 使用 `IShellLink` COM 接口解析快捷方式目标路径
- 与 KNOWN_TOOLS 数据库中的工具名称匹配
- 匹配成功后将工具标记为已安装

**文件**：`desktop/src-tauri/src/agent_detector.rs`

#### 2.1.2 开始菜单扫描（新增）

**目标**：通过扫描开始菜单快捷方式检测 AI 工具

**实现方案**：
```rust
/// 扫描开始菜单，返回匹配的工具 ID 列表
fn scan_start_menu() -> Vec<String> {
    let mut found = Vec::new();
    let start_menu_dirs = [
        // 当前用户开始菜单
        PathBuf::from(std::env::var("APPDATA").unwrap_or_default())
            .join("Microsoft/Windows/Start Menu/Programs"),
        // 公用开始菜单
        PathBuf::from(std::env::var("PROGRAMDATA").unwrap_or_default())
            .join("Microsoft/Windows/Start Menu/Programs"),
    ];
    
    for dir in &start_menu_dirs {
        if !dir.exists() { continue; }
        if let Ok(entries) = walkdir(dir, 3) { // 递归 3 层
            for entry in entries.flatten() {
                let path = entry.path();
                if path.extension().and_then(|e| e.to_str()) != Some("lnk") {
                    continue;
                }
                // 匹配逻辑与桌面快捷方式相同
                let name = path.file_stem()
                    .and_then(|n| n.to_str())
                    .unwrap_or("")
                    .to_lowercase();
                for tool in KNOWN_TOOLS {
                    if name.contains(&tool.name.to_lowercase()) {
                        found.push(tool.id.to_string());
                    }
                }
            }
        }
    }
    found
}
```

**注意**：使用 `walkdir` crate 或手动递归，限制最大深度为 3 层以避免性能问题。

#### 2.1.3 增强 binary_paths（CodeBuddy 修复）

**问题**：CodeBuddy 的 `binary_paths: &[]` 导致无法通过路径匹配检测

**修复方案**：在 KNOWN_TOOLS 中为 CodeBuddy 补充常见的安装路径：

```rust
KnownTool {
    id: "codebuddy",
    name: "CodeBuddy (腾讯)",
    ...
    binary_paths: &[
        // 腾讯系 IDE 插件常见安装路径
        "%LOCALAPPDATA%/Programs/CodeBuddy/CodeBuddy.exe",
        "%LOCALAPPDATA%/Programs/CodeBuddy CN/CodeBuddy CN.exe",
        "%PROGRAMFILES%/CodeBuddy/CodeBuddy.exe",
        // VS Code 插件市场安装路径
        "%USERPROFILE%/.vscode/extensions/.../CodeBuddy.exe",
    ],
    exe_names: &["CodeBuddy.exe", "CodeBuddy CN.exe"],
}
```

**关键逻辑**：
- 补充 3-4 条常见安装路径到 `binary_paths`
- 保留 `exe_names` 全盘扫描作为 fallback
- 更新 `TraeCNDetector` 的 detect 逻辑，确保 Trae CN 路径优先匹配且不落入 Trae 的回退路径

**文件**：`static/app.js`

```javascript
// v0.8.25：版本号改为从后端 API 动态获取，消除硬编码
// 硬编码版本号作为 fallback（仅当 API 不可用时使用）
const APP_VERSION = '0.8.23';  // 保持为默认值，启动时异步更新
window.__LRC_VERSION__ = APP_VERSION;

// 启动时异步获取后端版本号
(async function fetchVersion() {
    try {
        const res = await fetch(`${API_BASE}/v1/health/system`);
        if (res.ok) {
            const data = await res.json();
            if (data.version) {
                // 更新全局版本号
                const newVersion = data.version;
                // 更新 APP_VERSION
                // 注意：由于 APP_VERSION 是 const，这里通过 window 属性更新
                window.__LRC_VERSION__ = newVersion;
                // 更新状态栏版本显示
                const versionEl = document.getElementById('status-version');
                if (versionEl) versionEl.textContent = 'v' + newVersion;
                const sysVersion = document.getElementById('sys-version');
                if (sysVersion) sysVersion.textContent = 'v' + newVersion;
                // 更新 meta version
                const metaVersion = document.querySelector('meta[name="version"]');
                if (metaVersion) metaVersion.content = newVersion;
            }
        }
    } catch (e) {
        console.warn('[LRC] 获取后端版本号失败，使用本地版本号:', e.message);
    }
})();
```

**关键逻辑**：
- 保留 `APP_VERSION` 常量作为启动时的默认值（fallback）

- 版本号更新后同步更新：状态栏显示、系统信息面板、meta 标签
- 网络不可达时静默降级，使用本地硬编码版本号

### 2.3 P1：模型测试按钮

**问题**：当前仅有"测试连接"按钮（验证 API 端点可达性），缺少"测试模型"按钮（验证模型本身与 LRC 的连通性）

**根因分析**：
- 前端 `static/index.html` 仅有 `testEmbedderConnection` 和 `testLlmConfig` 两个"测试连接"按钮
- 后端 `/v1/encode` 端点可用于测试模型，但前端未暴露对应的"测试模型"按钮
- 用户无法区分"API 可达"和"模型可用"两个不同状态

**修复方案**（3 个子任务）：

#### 2.3.1 后端新增 /v1/model/test 端点

**文件**：`src/v1_api.rs`

```rust
// POST /v1/model/test — 测试模型连通性
// 发送一段测试文本到编码器，验证模型是否正常响应
.route("/model/test", post({
    let store = metrics_store.clone();
    move || {
        let store = store.clone();
        async move {
            // 使用测试文本调用编码器
            let test_text = "这是一个模型连通性测试。";
            match store.lock().await.encode(test_text) {
                Ok(vector) => {
                    Ok(Json(serde_json::json!({
                        "ok": true,
                        "message": "模型响应正常",
                        "vector_dim": vector.len(),
                        "elapsed_ms": ... // 记录耗时
                    })))
                }
                Err(e) => {
                    Err((
                        StatusCode::SERVICE_UNAVAILABLE,
                        Json(serde_json::json!({
                            "ok": false,
                            "error": "model_test_failed",
                            "message": format!("模型测试失败: {}", e)
                        }))
                    ))
                }
            }
        }
    }
}))
```

**备选方案**：复用 `/v1/encode` 端点，前端发送固定测试文本。此方案更简单，但新增端点更符合 REST 语义且便于后续扩展。

**推荐方案**：新增 `/v1/model/test` 端点，原因：
1. 语义清晰：测试模型与编码文本是不同操作
2. 可扩展：未来可添加模型加载状态、模型版本等信息
3. 不影响现有 `/v1/encode` 功能

```javascript
// v0.8.25 新增：模型连通性测试
async function testModel() {
    const btn = document.querySelector('[data-action="testModel"]');
    if (!btn) return;
    
    const originalText = btn.innerHTML;
    setButtonState(btn, 'loading', '测试中...');
    
    try {
        const res = await fetch(`${API_BASE}/v1/model/test`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ text: '这是一个模型连通性测试。' })
        });
        
        if (res.ok) {
            const data = await res.json();
            showToast(`模型测试通过（维度: ${data.vector_dim}，耗时: ${data.elapsed_ms}ms）`, 'success', 5000);
            setButtonState(btn, 'success', originalText);
        } else {
            const err = await res.json();
            showToast(`模型测试失败: ${err.message}`, 'error', 5000);
            setButtonState(btn, 'error', originalText);
        }
    } catch (e) {
        showToast(`模型测试失败: ${e.message}`, 'error', 5000);
        setButtonState(btn, 'error', originalText);
    }
    
    setTimeout(() => setButtonState(btn, 'idle', originalText), 3000);
}
```

```javascript
// v0.8.25：选中 AI 工具后自动扫描 IDE 项目目录
async function onAgentSelected(agentId) {
    // 记录选中状态
    const selectedAgents = getSelectedAgents();
    
    // 如果是 IDE 类工具且有 project 扫描能力，自动扫描项目目录
    const agent = findAgent(agentId);
    if (agent && agent.category === 'ide') {
        try {
            const projects = await postMessageToParent('lrc-scan-ide-projects', {
                ide_ids: [agentId]
            }, 15000); // 15 秒超时
            
            if (projects && projects.length > 0) {
                // 自动填充检测到的项目目录作为默认值
                const projectListEl = document.getElementById('wizard-project-list');
                if (projectListEl) {
                    projectListEl.innerHTML = projects.map(p => `
                        <div class="project-item" data-path="${htmlescape(p.path)}">
                            <input type="checkbox" checked>
                            <span class="project-name">${htmlescape(p.name)}</span>
                            <span class="project-path">${htmlescape(p.path)}</span>
                        </div>
                    `).join('');
                }
                // 显示找到的项目数量
                showToast(`已自动检测到 ${projects.length} 个项目目录`, 'info', 3000);
            }
        } catch (e) {
            console.warn('[LRC] 自动扫描项目目录失败（可手动选择）:', e.message);
        }
    }
}
```
