# Loong Recall 核心算法道枢映射白皮书

> **版本**: v1.0
> **日期**: 2026-06-06
> **目的**: 为 LRC 的每一个工程特性建立与河图洛书/阴阳八卦哲学体系的严格映射，确保系统的技术实现与理论根基始终自洽，防止"语义漂移"。

---

## 一、总纲

### 1.1 什么是道枢映射

**道枢**（Dao Pivot）取自《庄子·齐物论》"彼是莫得其偶，谓之道枢"。在 LRC 中，道枢映射是指：

> 每一个工程特性，都必须能在洛书九宫格、河图阴阳、八卦变化的动力学中找到其对应的"自然法则"位置。该特性不是外部赋加的"管理规则"，而是从"道"的动力学中**自然涌现**的"内禀调节"。

### 1.2 审查标准

任何新增的工程特性，必须通过以下三项审查：

1. **几何对应**：该特性对应的洛书九宫格位置或河图几何关系是什么？
2. **动力学涌现**：该特性的行为是否可以从八卦的阴阳消长中自然推导出来？
3. **不冲突原则**：该特性是否与已有的道枢映射冲突？

如果某项特性找不到对应的哲学基础，则应考虑：
- 重新设计以符合核心范式
- 或明确标记为"过渡性工程补丁"，并设定到期重审日期

## 二、核心算法道枢映射

### 2.1 洛书编码 (LuoShuVector)

| 工程特性 | 道枢映射 |
|---------|---------|
| **9 维洛书向量** | 洛书九宫格，每宫对应一个维度。戴九履一，左三右七，二四为肩，六八为足，五居中央。 |
| **幻和约束** | 洛书幻和 = 15，任意行/列/对角线之和相等。编码器通过最小化偏离度来维持几何约束。 |
| **八卦归类** | 9 维向量经过 MirrorProject 降维映射到 8 个八卦类别，对应洛书九宫中除去中央五宫后的八宫。 |

**八卦**: ☰乾 ☱兑 ☲离 ☳震 ☴巽 ☵坎 ☶艮 ☷坤

### 2.2 镜像投影 (MirrorProject)

| 工程特性 | 道枢映射 |
|---------|---------|
| **镜像投影** | 河图"天一生水，地六成之"的镜像对称原理。向量在 9 维空间中通过镜像平面投影，得到 8 维八卦签名。 |
| **梯形聚焦** | 洛书"二四为肩，六八为足"的梯形结构。聚焦算子将向量能量向四正方位（坎离震兑）集中。 |

**几何对应**: 镜像平面 = 洛书九宫格的对角线平面，投影 = 向量在该平面上的正交投影。

### 2.3 递归合成 (RecursiveCompose)

| 工程特性 | 道枢映射 |
|---------|---------|
| **递归合成** | **震卦·雷 (☳)** — 萌发与整合。雷动则万物生，合成是将分散的记忆碎片聚合为新的抽象知识。 |
| **信息增量阈值** | **坤卦·地 (☷)** — 承载与收藏。大地承载万物，但也需要筛选——不是所有种子都能发芽。阈值确保只有具备足够"新信息"的合成才被允许，防止空洞的"压缩"冒充"创造"。 |
| **解析度标志** | **离卦·火 (☲)** — 光明与分辨。火光照亮细节，解析度标志让用户能在"抽象摘要"与"原始细节"之间自由切换。 |

**动力学涌现**: 合成的触发条件（同八卦类别 + 相似度 > 阈值 + 信息增量 > 阈值）对应震卦"一阳初动"——只有在条件成熟时（阳爻积累足够），才触发萌发。

### 2.4 道同构度调节器 (DaoRegulator)

| 工程特性 | 道枢映射 |
|---------|---------|
| **调节器本体** | **艮卦·山 (☶)** — 止息与警觉。山不动而观万象，调节器被动监控系统状态，在异常时发出调节信号。 |
| **阴阳失衡检测** | 阴爻与阳爻的比例偏离 1:1 时触发，对应八卦中阴阳消长的自然规律。 |
| **八卦分布熵监控** | 八宫均衡 = 太极圆融，八宫偏斜 = 阴阳失衡。熵值越低，失衡越严重。 |
| **耦合指数** | 五行生克关系在八卦分布中的体现。多指标同时异常 = 五行相克，需综合调节。 |
| **灾难性转折检测** | 艮卦"艮其背，不获其身"——无法阻止的坠落。当健康评分骤降时，检测器记录"压死骆驼的最后一根稻草"。 |
| **慢性退化检测** | 艮卦"艮其趾，无咎"——从小处开始警觉。长周期内持续缓慢下降，对应"温水煮青蛙"式的退化。 |
| **动态信息增量阈值** | **坤卦·地 (☷)** — 承载与收藏。调节器根据合成产物质量自动微调阈值，从静态经验值变为动态自适应的"活"参数。 |

**动力学涌现**: 调节器的所有调节动作，都可以从八卦的阴阳消长中推导：
- 阴盛（八卦集中）→ 调整检索权重，引导阳气（探索）注入
- 阳亢（合成过频）→ 提高合成阈值，以阴气（收藏）制衡
- 阴阳和谐（熵高且道同构度高）→ 适度加快衰减，维持动态平衡

### 2.5 混合编码器 (HybridLuoShuEncoder)

| 工程特性 | 道枢映射 |
|---------|---------|
| **ML 编码器** | **乾卦·天 (☰)** — 刚健与创造。语义编码器产生高维、丰富的向量表示。 |
| **统计编码器** | **坤卦·地 (☷)** — 承载与收藏。基于关键词频率的统计编码，朴素但稳定。 |
| **降级与冷却期** | **坎卦·水 (☵)** — 险陷与诚信。ML 编码器不可达时降级为统计模式（如水流绕过障碍），但恢复时需冷却期（如水需沉淀），防止频繁切换导致的震荡。 |

**动力学涌现**: 乾（ML 编码器）与坤（统计编码器）的交替，对应太极图中阴阳的此消彼长。冷却期 = 阴阳转换的"缓冲带"，防止突变。

### 2.6 用户反馈回路 (UserFeedback)

| 工程特性 | 道枢映射 |
|---------|---------|
| **显式反馈** | **离卦·火 (☲)** — 光明与分辨。用户主动标记，如火光直接照亮黑暗。 |
| **隐式反馈（被动反馈）** | **巽卦·风 (☴)** — 渗透与无形。风无形而能渗透万物，隐式反馈通过观察用户行为无声地校准系统。 |
| **两阶段确认** | **兑卦·泽 (☱)** — 润泽与沟通。高影响操作前先展示影响评估，如泽水滋润前先试探土壤。 |
| **隐私开关** | **坎卦·水 (☵)** — 深邃与诚信。水能载舟亦能覆舟，隐私保护是系统诚信的基石。 |

**动力学涌现**: 显式反馈 = 阳（主动），隐式反馈 = 阴（被动）。阴阳结合，形成完整的反馈闭环。

### 2.7 审计追踪 (AuditTrail)

| 工程特性 | 道枢映射 |
|---------|---------|
| **审计记录** | **坎卦·水 (☵)** — 深邃与诚信。水能照见万物，审计记录让系统的每一个行为都透明可追溯。 |
| **哈希链防篡改** | **坎卦·水 (☵)** — 水的连续性。哈希链如同水流，不可切断、不可逆流。每条事件包含前序哈希，形成不可篡改的"记忆之河"。 |
| **异步持久化** | **巽卦·风 (☴)** — 渗透与无形。持久化在后台线程中无声进行，不阻塞主流程。 |

**动力学涌现**: 坎卦"习坎，重险也"——审计追踪是系统在"险境"（错误、安全漏洞）中的最后防线。哈希链 = 坎卦中"水流而不盈"的连续性。

### 2.8 记忆垃圾回收 (MemoryGC)

| 工程特性 | 道枢映射 |
|---------|---------|
| **GC 本体** | **兑卦·泽 (☱)** — 润泽与平衡。泽水润物，但过满则溢。GC 清理过期记忆，维持记忆库的健康水位。 |
| **动态基线计时** | **兑卦·泽 (☱)** — 泽水的自然节律。使用均值+3σ 标准差作为动态阈值，而非固定间隔，减少无效警告。 |
| **隔离机制** | **艮卦·山 (☶)** — 止息与隔离。低质量记忆先隔离观察，而非直接删除，避免误伤。 |
| **隔离区淘汰** | **坤卦·地 (☷)** — 收藏与归藏。隔离期满的记忆最终归入大地，完成生命周期。 |

## 五、新增特性审查清单

当开发者在 LRC 中添加新的工程特性时，必须回答以下问题：

1. **[几何对应]** 该特性对应洛书九宫格中的哪个宫位？或河图中的哪个几何关系？
2. **[八卦映射]** 该特性对应哪个八卦？其行为是否与该卦的自然属性一致？
3. **[动力学涌现]** 该特性的触发条件和调节行为，是否可以从阴阳消长中自然推导出来？
4. **[不冲突检查]** 该特性是否与已有的道枢映射冲突？是否有两个特性映射到同一卦但行为相反？
5. **[过渡性标记]** 如果找不到对应映射，是否已明确标记为"过渡性工程补丁"并设定到期重审日期？
