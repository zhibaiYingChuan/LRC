# LRC v0.9.4 时间线与道同构度体验闭环审计报告

## 1. 审计目标

本报告针对以下用户反馈进行审计与修复约束定义：

- 结晶历史时间线不能及时更新，手动刷新也看不到最新事件。
- 演化时间线刷新后仍显示旧内容，无法区分空数据、失败和缓存数据。
- 道同构度健康评分偏低时，用户不知道分数含义、影响和处理方式。
- 重新计算、重新编码等高学习成本动作缺少自动化引导。

目标是建立两个可验证闭环：

1. 事件产生 → 持久化 → 查询 → 渲染 → 自动/手动刷新 → 异常可恢复。
2. 低分检测 → 原因解释 → 低风险自动处理 → 重新评估 → 结果记录。

## 2. 审计结论

### P0

1. 前端使用 `||` 处理评分默认值，会把合法的 0 分覆盖成默认高分。
2. 前端重复计算健康评分，与后端 `dao_isomorphism_score` 不是同一评分源。
3. 低分没有“原因—影响—建议动作”的可读解释。

### P1

1. 结晶历史请求最近 10 条通用事件后才过滤，结晶事件可能被截断。
2. 时间线请求失败或返回空数组时保留静态示例，用户无法判断真实状态。
3. 结晶完成、Sidecar 恢复或手动刷新后没有统一刷新闭环。
4. `lock_busy`、`loading`、`degraded` 可能被当成真实低分渲染。
5. 低分没有自动化的低风险处理，也没有处理后的重新评估。

### P2

1. 时间线没有稳定的 loading、empty、error、stale 状态展示。
2. 演化事件渲染依赖接口顺序，前端未显式按时间倒序。
3. 低分缺少评分可信度、更新时间和趋势说明。

## 3. 产品决策

### 3.1 自动化原则

用户不应先学习内部指标、洛书向量或重编码成本才能解决问题。系统采用：

- 低风险、无数据破坏操作：自动执行。
- 可能改变检索结果或记忆结构的操作：先解释影响，再由用户确认。
- 永久删除、批量隔离、修改模型或 API 配置：禁止由低分检测自动执行。

### 3.2 用户文案原则

评分不是“考试成绩”，低分不等于数据丢失。界面必须同时说明：

- 当前状态；
- 主要原因；
- 对搜索、结晶和排序的实际影响；
- 系统已自动做什么；
- 用户还可以做什么；
- 原始记忆不会因评分降低而自动删除。

建议档位：

| 分数 | 状态 | 用户理解 |
|---:|---|---|
| 80–100 | 稳定 | 当前结构稳定 |
| 60–79 | 需要关注 | 有轻微偏离，不影响基本使用 |
| 30–59 | 建议处理 | 可能影响结晶质量和排序稳定性 |
| 0–29 | 建议诊断 | 建议检查，但原始记忆仍安全 |

## 4. 修复方案

### 4.1 时间线

- 结晶历史使用 `event_types=synthesis_created` 查询，避免先截断后过滤。
- 首次加载、手动刷新和服务恢复时统一重新请求。
- 加载开始显示 loading；空数组显示暂无记录；失败显示错误和重试；失败时保留旧数据并标记过期。
- 显式格式化 `timestamp_ms`，按时间倒序排序。
- 不再使用静态示例冒充真实历史。
- 刷新操作使用单飞请求，避免自动刷新与手动刷新并发。

### 4.2 评分

- 前端直接使用后端 `dao_isomorphism_score` 作为唯一主评分源。
- 所有派生指标使用空值合并，保留真实 0 值。
- `lock_busy/loading/degraded` 只显示“正在处理/数据暂不可用”，不渲染成 0 分。
- 低分显示原因、影响和自动化处理说明。
- 第一阶段自动执行非破坏性刷新和重新评估；重编码、隔离和权重调整需要确认。

## 5. 验收标准

### 时间线

- 页面进入后自动加载真实事件。
- 新结晶事件能在刷新后显示。
- 最近 10 条非结晶事件不会遮蔽更早的结晶事件。
- 空数组不显示示例数据。
- 请求失败不伪装成成功，重试按钮可用。
- 时间线事件按时间倒序显示。

### 评分

- 后端返回 0 分时前端显示 0，而不是默认高分。
- 后端评分与前端中心评分一致。
- 低分页面明确说明影响，不使用“系统坏了”等恐慌文案。
- 低风险处理后自动重新评估并更新更新时间。
- 任何高风险动作执行前展示影响范围、可撤销性和预计成本。

## 6. 风险控制

- 自动处理必须有超时、取消和失败状态。
- 连续失败不得无限重试。
- 高风险操作必须二次确认。
- 低分数据不足时显示“评分可信度有限”，不执行激进动作。
- 时间线和评分更新失败时保留最近一次成功数据，并明确标记不是最新。
