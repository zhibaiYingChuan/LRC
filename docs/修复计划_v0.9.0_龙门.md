# 修复计划 v0.9.0 "龙门" — 前后端数据流断层修复

> 版本：v0.9.0
> 基于：审计报告 `审计报告_v0.8.48_前后端数据流断层.md`
> 定义者：swarmforge-specifier（问题定义 + 验收行为）
> 创作者：creator-product-designer（4 态状态机 + 渐退式降级 UI）

## 一、要解决的核心问题

v0.8.48 桌面版安装后，系统状态面板全线显示 `--`。经审计确认四条根因：

| 根因 | 类型 | 严重度 |
|------|------|--------|
| R1: catch 块遗漏 DOM 降级 | 代码缺陷 | P0 |
| R2: 端口发现异步竞态 | 架构缺陷 | P0 |
| R3: 部分 API 成功降级不完整 | 逻辑缺陷 | P1 |
| R4: 结晶引擎静默故障 | 可观测性缺失 | P2 |

## 二、修复项清单

### FIX-01：catch 块补充降级更新（P0）

**文件**：[app.js](file:///g:/code-memory/static/app.js)
**位置**：`loadSysStatusFloat` 的 catch 块

**当前代码**：
```javascript
} catch (e) {
    console.warn('[Loong Recall] 系统状态浮窗加载失败:', e.message);
}
```

**目标代码**：
```javascript
} catch (e) {
    console.warn('[Loong Recall] 系统状态浮窗加载失败:', e.message);
    setDegradedStatusFloat();  // ← 补充：将 "--" 渲染为 "不可用"
}
```

**验收**：sidecar 未启动时，浮窗字段显示"不可用"而非"--"

---

### FIX-02：Tauri 环境延迟首次浮窗加载（P0）

**文件**：[app.js](file:///g:/code-memory/static/app.js)
**位置**：`initSysStatusFloat` 中的 `setTimeout(loadSysStatusFloat, 600)`

**当前代码**：
```javascript
setTimeout(loadSysStatusFloat, 600);
```

**目标代码**：
```javascript
const initialDelay = isTauriEnv ? 2500 : 600;
setTimeout(loadSysStatusFloat, initialDelay);
```

**验收**：Tauri 环境 sidecar 端口为 3111 时，浮窗首次加载成功显示数据

---

### FIX-03：API_BASE 从 `<meta>` 标签同步读取（P0）

**文件**：[app.js](file:///g:/code-memory/static/app.js)
**位置**：`API_BASE` 初始化

**方案**：新增 `_readSidecarPortFromMeta()` 函数，在脚本执行第一时间从 `<meta name="lrc-sidecar-port">` 读取端口，作为初始 `API_BASE`。消除依赖异步 IPC 的竞态。

**验收**：`_readSidecarPortFromMeta()` 在 DOM 中检测到 meta 标签时返回正确端口号

---

### FIX-04：renderDashboard 部分成功降级（P1）

**文件**：[app.js](file:///g:/code-memory/static/app.js)
**位置**：`renderDashboard` 函数

**方案**：引入 `dashboardHealth` 对象追踪各数据源状态，逐面板检查可用性：

```javascript
const dashboardHealth = {
    system:   systemData ? 'ok' : 'failed',
    detailed: detailedData ? 'ok' : 'failed',
    dao:      daoData ? 'ok' : 'failed',
};
```

道同构度面板仅在 `health.dao === 'failed'` 时走降级渲染；记忆统计卡片仅在 `health.system === 'failed'` 时走降级。

**验收**：system 成功但 dao_metrics 失败时，记忆卡片正常显示，道同构度面板显示"数据暂不可用"

### FIX-06：后端 `--dev` CLI 标志 + 端口 3111（P1）

**文件**：[server.rs](file:///g:/code-memory/src/server.rs)
**位置**：CLI 参数解析 + 端口绑定

**方案**：
- 新增 `--dev` CLI 标志
- `--dev` 模式下强制绑定端口 3111，端口被占时直接报错退出（不做自适应）
- 前端通过 `/v1/health/system` 返回 `dev_mode: true` 字段识别开发模式

**验收**：
- `code-memory-server --dev` 启动后监听 3111
- `/v1/health/system` 返回 `"dev_mode": true`

### FIX-07：`/v1/health/system` 增加 `consolidation` 字段（P2）
