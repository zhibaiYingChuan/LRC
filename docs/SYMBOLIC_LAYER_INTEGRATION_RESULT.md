### 3.3 ★「UI 渲染时有时无」的真相：**是探针采样过早，不是 UI 缺陷**

排查中一度出现"后端稳定返回 1 个 symbolic，UI 有时渲染 1 个、有时 0 个"。
用三个探针逐层排除，最终**否证了 UI 缺陷假设**：

| 探针 | 做法 | 结论 |
|---|---|---|
| `cdp_same_call_probe.js` | 劫持 `fetch`，抓 **UI 自己那次**响应，与**同一时刻** DOM 对账 | 3/3 `CONSISTENT_PRESENT`（响应有 1 个，DOM 也 1 个） |
| `cdp_timing_probe.js` | 500ms 采样一次，记录"响应到达时刻"与"徽章首次出现时刻" | 响应 **11.9s/12.3s** 到达，**徽章与响应同一毫秒出现** |
| 旧 `cdp_symbolic_reason_probe.js` | 触发探索后**固定 sleep 11s** 再读 DOM | 11s 时 `nodes=0, badges=0, hasResp=false` ⇒ **读在响应到达之前** |

**根因**：explore 响应耗时 **10.4s~13.5s 波动**，而旧探针固定等 11s
⇒ 采样点落在响应到达之前，读到空 DOM。**UI 渲染本身无缺陷。**

**教训**：`cdp_symbolic_depth.js` 用的是**独立 fetch**（页面里另发一个请求）。
用"独立请求的响应"去解释"UI 那次渲染的 DOM"，属于**拿 A 次的证据解释 B 次的现象**；
而"固定等待"则把**时间竞态**伪装成了**功能缺陷**。
两者都会把**观测方法的问题**误报成**产品的缺陷**。

现 `cdp_symbolic_reason_probe.js` 与 `symbolic-layer-desktop-cdp.js`
均已改为**轮询"响应是否到达"**（劫持 fetch 取信号），不再固定等待。

### 3.4 附带观察：探索时延余量偏薄（非本轮引入）

回归时页面控制台出现 2 条 `SidecarTimeoutError`（`app.js:10272` 预算 15000ms）。

| 测量 | 结果 |
|---|---|
| `probe_explore_latency.js` 三查询 | 10.7s / 0.45s / 10.2s，**0/3 超预算** |
| `probe_explore_variance.js` 串行 4 轮（同查询） | min 10417 / avg 10492 / max 10591 ms，**0/4 超预算**，余量稳定 ~4.4s |

结论：稳态余量约 **4.4s**（10.5s / 15s），**未超预算**；
回归时的 2 条超时出现在多用例连续压力下，属**偶发逼近预算**，
非本轮改动引入（本轮只改前端标签文案与徽章分支，不涉及时延）。
作为**观察项**记录，不扩大本轮范围。

## 四、本轮修正的两个**判据自身错误**

| # | 错误判据 | 为什么会错 | 改正 |
|---|---|---|---|
| 1 | V3.2 断言"含「符号层推导边」" | 那是**落盘边**的措辞；本分区展示的是 `/cycle` **候选**（无记忆 ID） | 改为断言"含`结构算子来源`" |
| 2 | 用 PowerShell `-match '符号层'` 判定 | PowerShell 把 UTF-8 响应按 **Latin-1** 解码 ⇒ 中文变乱码 ⇒ 必然失配 | 改用 Python 按**原始字节**判定 |

> ★第 2 条一度让我误判为"符号层没出现"。**工具链的编码问题会伪装成产品缺陷**——
> 验收脚本必须按字节判定，不能依赖终端编码。
