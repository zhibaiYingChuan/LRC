## 三、发现的缺陷

### P0-1：前端 `loadSysStatusFloat` catch 块遗漏 DOM 降级更新

**文件**：[app.js](file:///g:/code-memory/static/app.js#L7818-L7821)

```javascript
  } catch (e) {
    // 静默失败：浮窗不影响主功能
    console.warn('[Loong Recall] 系统状态浮窗加载失败:', e.message);
  }
```

**问题**：当 `fetchWithTimeout` 抛异常（sidecar 未启动、连接被拒绝、DNS 失败、超时），catch 块仅打印日志，**不更新 DOM**。所有字段保留 HTML 初始的 `"--"`。

**触发场景**：
1. sidecar 未启动（最常见）
2. sidecar 端口自适应后 API_BASE 指向错误端口（见 P0-2）
3. 网络不可达、超时

**严重程度**：P0 — 用户可见的静默故障，无任何降级信号。

---

### P0-2：Tauri 环境 API_BASE 端口硬编码 + 竞态

**文件**：[app.js](file:///g:/code-memory/static/app.js#L54-L74)

```javascript
const DEFAULT_API_BASE = isTauriEnv
  ? 'http://127.0.0.1:3099'  // Tauri 环境：硬编码 3099
  : (window.location.origin || 'http://localhost:3099');
let API_BASE = new URLSearchParams(window.location.search).get('api') || DEFAULT_API_BASE;
```

**问题**：`API_BASE` 初始固定为 3099。虽然 `init()` 中（[app.js:3429-3450](file:///g:/code-memory/static/app.js#L3429-L3450)）有 IPC `get_sidecar_status` 异步更新端口，但存在竞态：

```
T0:     页面加载，API_BASE = "http://127.0.0.1:3099"
T0+?ms: init() 中 IPC get_sidecar_status 等待 sidecar 状态扫描
T0+600ms: setTimeout(loadSysStatusFloat, 600) 触发
         → 使用旧 API_BASE (3099) 发起请求
         → sidecar 实际在 3099 则成功，否则全部失败
T0+?ms: IPC 返回（但首次请求已发送）
```

**触发场景**：
1. 端口被占用 → sidecar 自适应到其他端口
2. 开发模式下 sidecar 在 3111 但前端仍请求 3099
3. 首次安装启动时 sidecar 响应慢

**严重程度**：P0 — 端口不匹配导致后端可达但前端请求失败。

---

### P1：`renderDashboard` 部分 API 成功时降级逻辑不完整

**文件**：[app.js](file:///g:/code-memory/static/app.js#L1200-L1202)

```javascript
if (!systemData && !daoData) {
    throw new Error('无法连接到 API 服务...');
}
```

**问题**：`Promise.allSettled` 并行请求三个端点后，仅当 `systemData` 和 `daoData` 都为空时才走错误路径。当 `/v1/health/system` 成功但 `/v1/health/dao_metrics` 失败时：
- 条件 `!systemData && !daoData` 为 false → 不抛异常
- 代码走正常路径 → `renderDashboard(systemData, null, daoData)` 中 `daoData = null`
- 道同构度面板依赖的字段缺失 → 显示 `"--"`

**严重程度**：P1 — 部分降级，用户看到部分数据但道同构度面板异常。

---

### P2：结晶引擎无可观测端点

**文件**：[server.rs](file:///g:/code-memory/src/server.rs#L842-L875)

**问题**：结晶流水线每 5 分钟轮询一次，但失败时仅 `eprintln!`。前端无法区分"结晶未触发"、"结晶执行中"、"结晶已失败"三种状态。

**用户影响**：结晶计数一直为 `--`，用户不知道是正常等待还是引擎故障。

## 五、根因链

```
根因 P0-1（直接原因）
  └→ 前端 catch 块遗漏 DOM 降级 → 所有字段保留 "--"

         加剧因素 P0-2（前置条件）
           └→ API_BASE 端口竞态 → fetch 发送到错误端口 → 全部失败 → 触发 P0-1

根因 P1（恶化因素）
  └→ 部分 API 成功时 doaMetrics 空 → 道同构度面板 "--"

根因 P2（长期债务）
  └→ 结晶引擎静默故障 → 结晶计数永远为 0 → 用户困惑
```
