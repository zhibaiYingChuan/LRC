# 结构观察分数（原“系统健康评分”）

> 结论先说：仪表盘的环形分数是**记忆结构指标**，不是内容健康分，也不是检索/答题质量分。
> 它不能证明记忆内容正确，也不能用来对外宣称“健康度 90 分”。

## 一、公式

实现位置：`core/lrc-algo/src/engine/dao_regulator.rs` 的 `composite_health_score()`。

### 非语义编码（统计模式）

| 分量 | 权重 | 说明 |
|---|---:|---|
| 道同构度 `dao_score` | 0.35 | 9 维激活与幻和几何的一致程度 |
| 八卦均衡 `bagua_entropy / 3` | 0.20 | 记忆类型分布的均衡度 |
| 洛书偏离 `1 - avg_deviation / MAX` | 0.20 | 9 维坐标偏离幻和约束的程度 |
| 合成健康 `1 - 2 × synthesis_ratio`（>50% 记 0） | 0.15 | 合成记忆占比 |
| 耦合健康 `1 - coupling_score` | 0.10 | 调节器耦合度 |

综合分 = 上述五项加权和，裁剪到 `[0, 1]` 后 ×100。

### 语义编码（ML 模式）

语义编码器的投影是**语义画像**，不是幻方构造。实测洛书偏离中位数约 1.84
（p95 约 2.04，结构最大值 2.0456），指标长期饱和；若仍按 55% 权重计入，
综合分会被结构性压低（实测上限约 0.39），并让“重新编码”看起来能修复它
——但重编码只会得到同一投影。

因此 ML 模式下**排除**道同构度与洛书偏离，剩余三项按 0.45 重新归一化：

```text
综合分 = (八卦均衡 × 0.20 + 合成健康 × 0.15 + 耦合健康 × 0.10) / 0.45
```

## 二、它能说明什么

- 记忆类型分布是否均衡、合成记忆是否过多、调节器是否与记忆库强耦合。
- 结构长期漂移时，作为“值得看一眼”的观察信号。

## 三、它不能说明什么

- **不是内容正确性**：记错的事实、过期的偏好不会因此扣分。
- **不是检索质量**：不预测 Recall@K / MRR / 答题准确率。
- **不是写入质量**：`absorb` 的误记、漏记、污染都不在公式里。
- **不是可用性**：分数低不等于服务不可用；分数高也不等于检索准。

真正影响使用体验的指标应单独看：检索命中率、写入失败率、重复记忆数、P95 延迟、
沉淀结果（`lrc doctor --capture`）。

## 四、为什么改名

原名称“系统健康评分”会让用户以为它衡量内容健康，甚至被用来对外宣称“健康度”。
前端已统一改为“结构观察（非内容健康）”，环图标签为“结构评分”（随下一个版本发布）；
后端字段与公式保持不变（兼容旧客户端与历史快照）。
