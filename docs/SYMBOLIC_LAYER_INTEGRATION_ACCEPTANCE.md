## 三、接入参数（需你确认）

### 3.1 门控取值建议

| 门控 | 建议 | 理由 |
|---|---|---|
| `LRC_DAOTI_CYCLE=1` | ✅ 开 | 符号层**候选**（读端），只读无副作用 |
| `LRC_DAOTI_BUILD_EDGES=1` | ✅ 开 | 符号层**候选边**（不落图时纯计算） |
| `LRC_DAOTI_WRITE_BACK` | ⚠️ **先关** | 它会**写图**（有副作用）。建议先观察不落边，确认输出合理后再开 |
| `LRC_DAOTI_REFLECT` | ⚠️ **先关** | 会**改 3222 状态**（副作用） |
| `LRC_DAOTI_NAVIGATE` | ⚠️ **先关** | 依赖 3222，且此前实测 +2.0~2.3pp **未达 8pp 门槛** |

> **原则**：先只开**只读**的两个，把有副作用的三个留到输出确认合理之后再开。
> 这样"看不到内容"与"内容不对"可以分开归因。

### 3.2 数据准备

| 项 | 说明 |
|---|---|
| 开发端库现状 | `event_id`=0 条 ⇒ **记录层联想不到东西**（已知，非缺陷） |
| 是否写入测试数据 | 若要验证**记录层+符号层并存**，需先写入带 `event_id` 的测试记忆 |

### 3.3 如何区分"接入失败"与"数据不足"

| 现象 | 归因 |
|---|---|
| 无 `═══ 联想 · 记录型关联 ═══` 分区 | **正常**（dev 库无 `event_id`） |
| 无 `═══ 联想 · 符号层候选 ═══` 分区 | **需查**：门控是否注入 3111？3223 是否可达？ |
| 有分区但内容为空 | 看是否给了原因码（V2.5） |
