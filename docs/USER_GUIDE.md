# Loong Recall 用户说明书

> **给 AI 装上记忆的本地服务** — 接入 IDE，AI 就能按需检索代码、跨会话记住关键约定与决策。
>
> 版本：**v0.9.9** | 适用于：Trae / Trae CN / Cursor / VS Code / Windsurf / Claude Desktop 等支持 MCP 协议的 AI 工具
>
> 本文面向**使用者**。想了解实现原理与能力实测数据，请看 [README](../README.md)；想了解本版本的修复内容，见 [CHANGELOG](../CHANGELOG.md)。

---

## 一、它解决什么问题

用 AI 写代码时，大概率遇到过这两种尴尬：

**尴尬一：不知道代码在哪。** 想让 AI 改某个功能，却不知道它在哪个文件。只能手动翻目录 → 搜关键词 → 复制粘贴几百行代码给 AI。每次都这样。

**尴尬二：AI 每次都失忆。** 你和 AI 约定了"用 pnpm"、"端口 8080"、"数据库 PostgreSQL"。第二天新开会话，它全忘了。

Loong Recall 给 AI 装两个能力：

| 能力 | 工具 | 一句话说清楚 |
|------|------|------------|
| **代码定位** | `search_code` | 知道函数名/变量名就能快速定位；配置 LLM 后可用自然语言 |
| **项目记忆** | `remember` / `recall` | 告诉 AI 一次约定，以后每次对话它都记得 |
| **记忆联想** | 联想中心 | 想起**没有共同关键词、但确实相关**的记忆（如"游西湖"→"楼外楼"） |

**最关键的是：你不需要做任何额外操作。** 配好规则后，AI 会自动判断何时该搜代码、何时该查记忆。你只管正常聊天。

### 30 秒理解它怎么工作

```
你问："我们上次决定用哪个数据库来着？"
        ↓
AI 内部自动调用 recall 工具，检索你的历史记忆
        ↓
AI 回复："（根据记忆 #3）你之前选择了 PostgreSQL，原因是需要 JSONB 和全文搜索"
```

整个过程你只看到 AI 的回答，中间的工具调用对你**完全透明**——就像开车不需要关心发动机怎么点火。

## 二、安装：下载桌面端（推荐）

前往 [Releases 页面](https://github.com/zhibaiYingChuan/LRC/releases) 下载对应平台的**桌面安装包**：

| 平台 | 安装包文件名 |
|------|------------|
| Windows | `lrc-desktop-v0.9.9-windows-x86_64-setup.exe` |
| macOS | `lrc-desktop-v0.9.9-macos-arm64.dmg` |
| Linux | `lrc-desktop-v0.9.9-linux-amd64.deb` 或 `...-linux-x86_64.AppImage` |

> ⚠️ **注意区分**：Release 里形如 `lrc-v0.9.9-windows-x86_64.exe` 的文件是 **CLI 命令行工具**（供脚本调用），**不是安装包**，双击无法安装。安装请认准 `lrc-desktop-*` 开头的文件名。

双击安装并启动，桌面端会自动完成所有配置：**检测 AI 工具 → 写入 MCP 配置 → 写入 AI 规则文件**。完成后重启 IDE 即可使用。

> 💡 **安装包为什么只有几 MB？** 是设计使然——语义模型按需下载（首次约 100~400MB，自动走国内镜像），道体推演引擎为独立研究资产不随产品分发。详见 [README 的道体边界说明](../README.md)。

## 三、首次启动：三步配置向导

首次打开桌面端会进入配置向导（三步）：

### 第 1 步 · 检测工具

自动扫描本机已安装的 AI 工具并分类展示（IDE 类 / 桌面应用类 / 命令行工具类），**IDE 优先**。

勾选你要接入的工具（Trae / Trae CN / Cursor / VS Code / Windsurf / CodeBuddy / Qoder 等），桌面端会**自动写入 MCP 配置，无需手动编辑任何 JSON**。

> 扫描结果有误时，可用工具旁的**齿轮图标**手动修正实际安装情况；也支持批量应用修正。
>
> 状态栏的「已停止 / 不可达」文本可点击 → 弹出启动服务弹窗；右下角数据目录路径可点击 → 直接打开文件夹。

### 第 2 步 · 配置 LLM（可选）

配置后可用**一句自然语言**搜索代码和记忆。下拉可选：**DeepSeek（推荐）**、通义千问、智谱 GLM、腾讯混元，或选「暂不配置」。

> **暂不配置完全没关系**——不配也能使用基础的代码搜索与记忆功能，配置 LLM 仅用于增强**自然语言查询**（把"这个项目的认证逻辑在哪里"翻译为精确检索词）。你随时可以在「设置」里补上，无需重启。API Key 使用 AES-256-GCM 加密存储在本地，绝不上传。

### 第 3 步 · 完成

桌面端在后台索引你选的项目代码。索引完成后，AI 工具就能直接查询这段代码的记忆了。

> 🔁 **配置随时可改**：设置页的「项目切换」可更换索引目录（切换后服务重启并重新索引代码）；设置页也提供「重置向导」可重走一遍配置流程。

### 首页：3 分钟走通完整流程

三步各点一次，你就明白它是怎么用的了。首页顶部还有两个常驻入口：

- **搜索框**：输入想找的内容直接回车
- **＋ 记一笔**：弹窗填写内容、类型（事实/偏好/决策/代码上下文/对话/经历/结晶知识）、重要性、标签、项目，以及**事件 ID**与**涉及实体**（见第六节）

## 五、联想中心：它帮你想起什么

这是 LRC 区别于普通搜索的地方。**搜索是"找字面像的"，联想是"想起相关的"**——即使两段记忆**没有任何共同关键词**。

进入「联想中心」，三个视图：

| 视图 | 用途 |
|------|------|
| **试试看** | 输入一句话，看它想起什么。**示例问题由你自己的记忆生成**（不是硬编码），库里没有可构造示例时整块隐藏，不显示点不通的假引导 |
| **联想足迹** | 历史联想记录。可按「只看连续联想」「只看有明确由来的」筛选；可一键清除（清除后重启仍不显示） |
| **小统计** | 联想次数、平均想起几条、两路都命中、避免跑偏 |

### 两类关联，要分清

界面上把两类证据**分开显示**，不混淆：

| 类型 | 含义 | 可信度 |
|------|------|--------|
| **记录关联** | 同一趟行程（`event_id`）、共享同一份文件、互相结晶而来 | 由记录**必然成立** |
| **结构推导** | 由因果/时序/约束等逻辑关系推导出的连接 | **可能不成立**，带独立徽章 |

### 遇到空态是正常的

记忆库里确实没有相关内容时，它会**诚实告诉你**，而不是硬凑答案：

```text
你的记忆库里还没有和「量子物理是什么」相关的内容。
这次没有想起相关的念头——不是联想坏了，是记忆里还没有记过这类事情。
```

> **为什么一开始联想效果不明显？** 因为**关联需要原料**。刚装好时库里是空的，或记忆之间没写关联字段，算法再强也无从推导。用一段时间、记够内容后，联想质量会随记忆增长而提升。详见 [README 的「原料瓶颈与当前边界」](../README.md#原料瓶颈与当前边界)。

## 六、让 AI 真正用起来：规则文件

桌面端会自动写入 AI 规则文件（如 `~/.trae/rules/lrc-memory.md`）。规则告诉 AI 四件事：

### 规则 1：会话开始时先 recall

回复任何问题之前，先调用 `recall` 检索项目记忆，获取已有上下文。

### 规则 2：遇到不确定的模块时优先 recall

需要了解某个模块、函数或概念时，**优先 recall 而非直接读源文件**——这能减少重复读文件导致的上下文溢出。

### 规则 3：完成任务后自动同步记忆

每次完成代码修改后，自动检查并同步记忆库（新增模块、改端点、改架构等）。

### 规则 4：写「经历」时填 `event_id` —— 这是联想的唯一依据

**这是最容易被忽略、却最关键的一条。**

记忆之间能互相联想，靠的**不是内容相似**，而是**它们来自同一次经历**。例：`游西湖` 与 `吃楼外楼` 语义上毫不相关，但只要同属"一次杭州之行"，它们就该能互相联想——这是任何相似度算法都给不出的连接。

- `memory_type` 用 `experience`（区别于 `fact`：后者是客观信息，不是"我经历过什么"）
- `event_id` 由 AI 生成并复用，建议「类型-对象-时间窗」，如 `trip-hangzhou-2026-09`
- 一次写多条时，用 `batch_remember` 在**批次级**传一次 `event_id` 即可
- `entities` 填内容里**明确出现**的人/地/时/物（name + kind），**只做誊写、不做推断**

> ⚠️ **不填 `event_id`，这些记忆之间就无法互相联想**——它们的关联依据（同一次经历）从未被记录，事后无法补。

## 七、搜索模式怎么选

| | Fast Match（默认） | Smart Match | LLM 增强 |
|---|---|---|---|
| **怎么搜** | 精确关键词匹配 | 本地语义理解 | 你的 LLM 翻译查询 → Fast Match |
| **适合** | 知道函数名/变量名，懒得翻文件 | 离线环境下用自然语言描述意图 | 有 LLM API，用自然语言描述意图 |
| **依赖** | 零，纯 Rust | 首次下载模型（约 95MB） | 需 LLM API |
| **内存占用** | < 10 MB | 约 200 MB | < 10 MB |

**日常 Fast Match 就够用**，不用纠结。桌面端安装包已包含 ML 能力（语义模型按需下载）。

```bash
# 从源码编译时按需选择
cargo build --release --features server        # 仅 Fast Match
cargo build --release --features server,ml     # 含 Smart Match（离线语义搜索）
```

> 内网/离线环境？参考 [Smart Match 离线安装指南](OFFLINE_MODEL_GUIDE.md)。

### 本地语义模型

默认根据系统语言自动选择：

| 系统语言 | 模型 | 维度 | 体积 |
|---------|------|------|------|
| 中文环境 | `BAAI/bge-small-zh` | 512 维 | 约 95MB |
| 其他语言 | `sentence-transformers/all-MiniLM-L6-v2` | 384 维 | 约 80MB |

下载策略：**国内镜像优先**（HfMirror → ModelScope）→ 断点续传 → 失败按 2s/4s/8s 指数退避重试 3 次 → 仍失败则**降级到 TF-IDF** 保证基础功能可用。

**模型管理 CLI**：

```bash
code-memory-server model list                  # 列出已下载模型
code-memory-server model download BAAI/bge-small-zh
code-memory-server model use BAAI/bge-small-zh # 切换默认模型
code-memory-server model remove BAAI/bge-small-zh
```

## 八、LLM 配置

### 支持的提供商

设置页可选：**DeepSeek**、通义千问、智谱 GLM、MiniMax 海螺、Kimi 月之暗面、阶跃星辰、百川智能、讯飞星火、腾讯混元、**自定义 API**（兼容 OpenAI 协议的任何地址）。

### 三种配置方式

1. **桌面端向导**（推荐）：首次启动第 2 步，或设置页随时修改
2. **设置页可视化配置**：选提供商 → 填 API Key → 保存，**即时生效无需重启**
3. **环境变量 / 命令行**（CLI 用户）：

```bash
code-memory-server --src-dir ./src --stdio \
  --llm-api "openai:sk-your-deepseek-key:deepseek-chat:https://api.deepseek.com/v1"
```

### 注意事项

- **不配置 `--llm-api`**：Fast Match 照常用，行为完全不变
- **翻译失败时**：自动回退到原始查询，不影响搜索功能
- **隐私**：只有查询文本发给 LLM，**不发送任何代码**
- **成本**：每次翻译约 40-50 Token。DeepSeek 每天 100 次查询 **< ¥0.01/月**

## 九、信任中心与数据安全

### 一键隐私检查

100ms 内获取完整隐私报告：存储位置、大小、网络访问、加密状态。

### 数据存储位置

所有数据**本地优先**，桌面端默认存储在 `~/.loong-recall/global/data/`（全局模式）。

| 模式 | 数据位置 | 适用 |
|------|---------|------|
| 全局模式（桌面端默认） | `~/.loong-recall/global/data/` | 跨项目共享记忆 |
| 项目指纹模式 | `~/.loong-recall/projects/{指纹}/data/` | 按项目隔离 |

### 隐私承诺

- 数据不出本地，所有编码、检索、合成均在本地完成
- 不收集遥测、不埋点、不上报
- 源代码索引驻留内存，不写磁盘
- 加密混淆存储 + **哈希链防篡改审计** + 完整性封印验证
- 仅在配置 LLM 时，查询文本（**非源代码**）会发送到你的 LLM API

### 备份与恢复

信任中心提供：**立即备份**（本地创建快照，保留最近 4 份）、**导出**（下载 JSON 到本地）、**导入**（从 JSON 恢复）、**数据迁移**（扫描历史遗留的分散数据，按记忆 ID 去重合并，原文件保留 `.bak`）。

> 换电脑迁移：复制 `~/.loong-recall/` 目录到新电脑即可。

| 类别 | 工具 | 用途 |
|------|------|------|
| **代码搜索** | `search_code` `codebase_stats` | 关键词定位代码、查看索引状态 |
| **记忆管理** | `remember` `batch_remember` `recall` `forget` `update_memory` `list_memories` `memory_stats` `archive` `correct_memory` `recall_enhanced` | 写入、批量写入、检索、删除、更新、列表、统计、归档、修正、增强检索 |

### 手动配置 MCP（CLI 用户）

桌面端会自动配置。从源码编译的 CLI 用户需手动写入。**HTTP 模式**（连接已常驻的服务）：

```json
{
  "mcpServers": {
    "lrc-memory": {
      "type": "http",
      "url": "http://127.0.0.1:3099/mcp"
    }
  }
}
```

**stdio 模式**（由 AI 工具拉起二进制）：

```json
{
  "mcpServers": {
    "lrc-memory": {
      "command": "code-memory-server",
      "args": ["--src-dir", ".", "--stdio"],
      "env": {
        "HF_ENDPOINT": "https://hf-mirror.com",
        "LRC_MODEL_MIRROR": "hf-mirror"
      }
    }
  }
}
```

| 客户端 | 配置文件 |
|--------|---------|
| Trae | `%APPDATA%/Trae/User/mcp.json` |
| Trae CN | `%APPDATA%/Trae CN/User/mcp.json` |
| Cursor | 项目根 `.cursor/mcp.json` |
| VS Code | 项目根 `.vscode/mcp.json` |
| Windsurf | `%APPDATA%/Windsurf/User/globalStorage/mcp.json` |
| Claude Desktop | `%APPDATA%/Claude/claude_desktop_config.json` |

也可用 `code-memory-server --install-ide <IDE>` 自动写入；`--list-ides` 列出全部支持的工具。

## 十一、常见问题

### Q：需要每次都说"请用 recall 搜索"吗？

**不需要。** 配好规则文件后 AI 会自动判断。你只需要正常问。

### Q：AI 会不会滥用记忆，把无关的也记下来？

**不会。** 规则里写明了触发条件（"技术决策"、"用户偏好"），不会记录闲聊。你也可以自行调整触发条件。

### Q：为什么 AI 回复里出现"（根据记忆 #3）"？

这是**有意设计**——让记忆**可见**，你能看到它在起作用，也能反过来校验准确性。

### Q：记忆突然搜不到了？

1. 记忆文件是否存在（信任中心「查看记忆文件」）
2. 搜索词太模糊？换更精确的关键词，或配置 LLM 增强
3. 联想/检索返回**诚实空态**时，说明库里确实没有相关内容——不是坏了

### Q：Fast Match 和 Smart Match 怎么选？

日常用 Fast Match（默认）。只有需要**模糊描述式搜索**（"处理重试的代码"）时才需要 Smart Match。两者可随时切换，不影响已有记忆。

### Q：本地语义模型下载失败怎么办？

三级降级：自动重试（2s/4s/8s）→ 切换镜像（HfMirror → ModelScope）→ 回退 TF-IDF。基础功能始终可用。

### Q：改了规则文件需要重启吗？

**不需要。** 规则是 `.md` 文件，IDE 每次对话会自动读取最新内容。

## 十二、故障排查

### 桌面端打开后服务没自动启动？

v0.9.9 已修复此问题（根因是自动启动判据选中了"是否走过向导"，而正常使用不需要走向导）。若仍遇到，点击状态栏「已停止 / 不可达」文本 → 弹出启动服务弹窗 → 点「启动服务」。

### 编译失败（从源码安装）

```bash
# "could not find `server` in `features`" → Rust 版本太旧
rustup update stable

# crates.io 下载超时 → 配置 Cargo 国内镜像

# link.exe 找不到 → 安装 Visual Studio Build Tools，勾选"C++ 桌面开发"

# os error 32（文件被占用）→ sidecar 进程在运行，先停止再编译
```

### 端口被占用？

LRC 支持端口自适应（会自动尝试 `3099-3198` 范围）。也可手动指定：`code-memory-server --src-dir ./src --port 3098`。查找占用：`netstat -ano | findstr :3099`。

### IDE 中 MCP 图标灰色 / 不显示？

1. 确认 MCP 配置文件路径正确（用正斜杠 `/`）
2. 确认二进制文件存在（用绝对路径更稳妥）
3. 在终端手动运行 MCP 命令看报错
4. **完全退出** IDE 再打开
5. 确认 IDE 的 MCP 功能已启用

### 仪表盘打开是空白页？

确认服务以 HTTP 模式启动（`--port 3099`）；stdio 模式不开放 HTTP 端口，仪表盘不可用。尝试 `Ctrl+F5` 强制刷新，并检查浏览器控制台（F12）报错。

## 十三、进阶：从源码编译

```bash
git clone https://github.com/zhibaiYingChuan/LRC.git
cd LRC
cargo build --release --features server,ml
./target/release/code-memory-server --src-dir ./src --port 3099
```

**常用启动参数**：

| 参数 | 说明 |
|------|------|
| `--src-dir <路径>` | 要索引的项目源码目录（默认当前目录） |
| `--port <端口>` | HTTP 端口（默认 `3099`） |
| `--stdio` | stdio 传输模式（IDE 标准 MCP） |
| `--global` | 记忆跨项目共享（`~/.loong-recall/global/data/`） |
| `--data-dir <路径>` | 自定义数据根目录 |
| `--llm-api <配置>` | 配置 LLM 查询翻译 |
| `--daemon` | 后台守护模式（供桌面端调用） |
| `--install-ide <IDE>` | 自动配置指定 IDE 的 MCP 连接 |
| `--list-ides` | 列出支持的 IDE / 工具 |

> 完整参数见 `code-memory-server --help`。

**快速安装脚本**（需已装 Rust）：Windows 双击 `install.bat`；Linux/macOS 运行 `bash install.sh`。脚本会检测 Rust 环境、编译、搜索本地 IDE 并创建 MCP 配置（已有配置时提示手动合并，不覆盖）。

**提交前检查**（贡献者）：仓库自带 Git 钩子，克隆后执行一次启用，提交前自动跑 5 项检查：

```powershell
.\scripts\enable_git_hooks.ps1
```
