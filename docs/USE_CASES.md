# 使用场景

本文档描述 Loong Recall 的典型应用场景与最佳实践。

---

## 场景一：IDE 中的 AI 编程助手

### 适用情况

你在 Trae、Cursor 或 VS Code 中使用 AI 助手进行日常开发。

### 配置方式

将 Loong Recall 配置为 MCP 服务，接入 IDE：

```json
{
  "mcpServers": {
    "loong-recall": {
      "command": "path/to/code-memory-server",
      "args": ["--src-dir", "path/to/your/project/src", "--stdio"]
    }
  }
}
```

### 实际效果

- **代码搜索**：用自然语言描述要找的代码，如 "处理用户认证的中间件在哪？"
- **决策记忆**：AI 记住你之前的技术选型决策（如 "我们决定用 PostgreSQL 而非 MySQL"），在新对话中自动引用
- **偏好记忆**：AI 记住你的代码风格偏好（如 "4 空格缩进"、"使用 pnpm"），持续保持一致
- **项目约定**：团队编码规范、API 端口分配等约定自动沉淀为项目知识

### 最佳实践

- 对于重要决策，使用 `importance=8` 以上确保长期保留
- 为不同项目使用 `--db-path` 隔离记忆，避免跨项目混淆
- 定期运行 `archive` 清理过期记忆

## 场景二：AI 客服 / 对话 Agent

### 适用情况

你正在构建一个需要跨会话记住用户信息的 AI 对话系统。

### 工作流程

```
用户首次对话 → Agent 记住用户偏好 → 用户离开
    ↓
用户再次对话 → Agent 自动召回历史记忆 → 无缝延续上下文
```

### 实际效果

- **用户画像**：自动积累用户的偏好、历史问题、反馈
- **跨会话上下文**：用户不需要重复说明之前的问题
- **自动知识抽象**：多次相似问题自动合成 FAQ 条目（程序记忆）

### 最佳实践

- 为每个用户使用独立的 `project` 标识隔离记忆
- 使用 `memory_type="preference"` 记录用户偏好
- 使用 `memory_type="conversation"` 记录对话摘要
- 使用 `memory_type="decision"` 记录用户做出的关键决策

## 场景三：个人知识管家

### 适用情况

你希望 AI 助手在日常对话中自动积累和组织你的知识。

### 工作流程

```
日常对话 → 关键信息自动记录为记忆
    ↓
同类记忆达到一定条件 → 自动合成抽象知识
    ↓
跨会话检索 → 知识持续可用
```

### 实际效果

- **决策日志**：所有重要决策自动记录，可随时回顾
- **学习路径**：学习过程中的关键概念自动关联，形成知识网络
- **项目历史**：参与过的项目关键信息不会随时间遗忘

### 最佳实践

- 使用 `--global` 模式让所有项目共享同一个记忆库
- 定期查看 `memory_stats` 了解记忆库的组成和健康度
- 使用 `list_memories` 按类型或时间浏览记忆

## 场景四：团队知识库

### 适用情况

为开发团队维护一个自动演化的项目知识图谱。

### 工作流程

```
开发者 A 的 AI 助手记录决策 → 记忆沉淀
开发者 B 的 AI 助手查询 → 获取历史决策上下文
新成员加入 → 直接检索项目历史知识
```

### 实际效果

- **新人上手**：新成员通过 `recall` 快速了解项目历史和约定
- **决策追溯**：每个技术决策都能追溯到原始上下文
- **知识不丢失**：核心成员的离职不会带走隐性知识

### 最佳实践

- 为团队项目设置专用的记忆数据库路径（`--db-path`）
- 关键架构决策使用 `memory_type="decision"` + `importance=10`
- 编码规范使用 `memory_type="preference"`
- 定期归档过期记忆，保持记忆库精简

---

## 通用最佳实践

### 记忆类型选择

| 内容性质 | 推荐类型 | 推荐重要性 |
|---|---|---|
| 客观事实（项目信息、技术栈） | `fact` | 6-7 |
| 用户偏好（风格、工具选择） | `preference` | 5-8 |
| 架构决策（选型、方案） | `decision` | 8-10 |
| 代码上下文（函数依赖、配置） | `code_context` | 5-7 |
| 对话摘要（讨论结论） | `conversation` | 4-6 |

### 标签策略

- 使用一致的标签命名（如 `tooling`、`database`、`api-design`）
- 为跨项目共享的记忆添加项目标签
- 不要使用过于具体的标签（如 `2024-q3-sprint-12`），它们很快失去意义

### 性能考量

- 单个记忆库在百万条规模以内无需担心性能
- 如果超过百万条，考虑按项目或时间范围分库
- CodeBERT 模式提供更高检索精度，但需额外 ~500MB 内存
