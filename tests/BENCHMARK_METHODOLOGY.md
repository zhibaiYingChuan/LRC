# Loong Recall 基准测试方法论白皮书 v1.0

## 一、设计哲学

### 1.1 为什么要自定义基准测试？

现有 AI 记忆系统的基准测试（如 LongMemEval）仅衡量"检索准确性"，
无法评估记忆演化、衰减管理、隐私保护、审计安全等 LRC 的核心能力。
我们创建这套基准测试，是因为**现有标准无法描述 LRC 正在解决的根本问题**。

### 1.2 三不原则

1. **不自欺**：所有测试指标均可被第三方用一行命令复现
2. **不隐藏**：公开所有测试的设计动机、实验设置、评判标准
3. **不独占**：任何系统都可以使用这套测试框架进行评测

## 二、测试架构

### 2.1 三层测试模型

| 层次 | 目标 | 对标 |
|------|------|------|
| 第一层：通用检索 | 证明基础能力不输于人 | LongMemEval、BEIR |
| 第二层：独有能力 | 证明只有 LRC 能做到的事 | 无现有对标 |
| 第三层：隐私信任 | 证明承诺可以被验证 | SOC2、GDPR 合规 |

### 2.2 实验环境

- **硬件**：标准开发机器（8 核 CPU、16GB RAM、SSD 存储）
- **操作系统**：Windows/macOS/Linux
- **Rust 版本**：stable 1.85+
- **数据规模**：模拟真实使用场景（1K 条记忆，表示个人用户数月的记忆积累）
- **测试隔离**：每次测试使用独立的 TempDir，确保无状态交叉污染

## 三、各测试详细方法论

### 3.1 大规模检索延迟

- **设计动机**：测量记忆系统的纵向扩展能力
- **实验设置**：预写入 1000 条记忆，执行 100 次检索
- **评判标准**：P50 < 500ms，P95 < 1000ms
- **对标**：与 Elasticsearch、Pinecone 的已知延迟数据对比

### 3.2 记忆衰减有效性

- **设计动机**：验证"重要信息不应该被遗忘"这一核心命题
- **实验设置**：等量高/低重要性记忆，观察检索排序
- **评判标准**：衰减因子运算正确，高重要性记忆的衰减更慢
- **对标**：Redis TTL（无差别过期）、Mem0 LRU（无优先级驱逐）

### 3.3 合成触发与质量

- **设计动机**：验证记忆系统的自主演化能力
- **实验设置**：写入 10 条数据库连接同类记忆，触发合成后检索"排查步骤"
- **评判标准**：Jaccard 相似度计算正确，合成后检索覆盖完整
- **对标**：无现有系统实现记忆合成

### 3.4 抗污染能力

- **设计动机**：验证记忆系统在噪声环境下的鲁棒性
- **实验设置**：80% 核心事实 + 20% 噪声注入，5 次检索一致性
- **评判标准**：≥3/5 一致性，噪声不进入前 5 结果
- **对标**：RAG 方案的上下文窗口污染问题

### 3.5 数据本地化

- **设计动机**：验证"本地第一"承诺
- **实验设置**：写入敏感数据，检查文件路径和内容
- **评判标准**：100% 本地存储，无外部网络请求
- **对标**：所有云服务方案（Mem0 Cloud、Zep Cloud、Pinecone）

### 3.6 审计防篡改

- **设计动机**：验证合规审计能力
- **实验设置**：写入记忆后检查哈希链和信任锚点
- **评判标准**：哈希链验证通过，锚点链验证通过
- **对标**：无现有记忆系统提供防篡改审计

## 四、可复现性保证

### 4.1 一行命令复现

```bash
git clone https://github.com/zhibaiYingChuan/LRC.git && cd LRC && cargo test --features server benchmark_
```

### 4.2 结果一致性

- 测试使用确定性 ID，保证每次运行的输入一致
- 使用 TempDir 保证无状态交叉污染
- 所有断言基于数学计算，不依赖外部服务

## 五、局限性与坦诚声明

1. **规模局限**：当前测试基于 1K 记忆规模，十万级以上规模尚未覆盖
2. **语义检索局限**：当前检索基于关键词匹配，ML 语义检索需要模型支持
3. **时间窗口**：未覆盖长时间（年）运行的稳定性测试
4. **多用户场景**：未覆盖多用户并发访问的性能测试
5. **攻击测试**：未覆盖恶意攻击（如对抗样本注入）场景
