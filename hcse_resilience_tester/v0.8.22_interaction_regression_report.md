## 六、发现的新问题

### 6.1 P0 问题（新发现）

#### IA-22-19：sidecar HTTP 连接资源耗尽不自愈

- **严重程度**：**P0**（影响 sidecar 可用性，但可通过 invoke 重启恢复）
- **发现过程**：本次审计首次运行测试脚本时，Phase 0 中 Python requests 测试触发 sidecar 端口 3099 上 CloseWait 连接堆积（36+ 个），导致后续所有请求（Python requests + CDP 内部 fetch）全部超时，但 sidecar 进程仍存活（PID 4228，端口仍 Listen）。
- **现象**：
  1. sidecar 进程存活（`Get-Process lrc-sidecar` 显示 PID 4228）
  2. 端口 3099 仍 Listen 状态
  3. 但有 36+ 个 `CloseWait` 状态的连接堆积
  4. 新请求（Python requests / PowerShell Invoke-WebRequest / CDP 内部 fetch）全部超时
  5. 前端 monitor 正确降级为 `isReachable=false, status="unknown", failCount=3`
  6. 但 banner 没有正确显示（`bannerHidden=true`，因为 `_setReachable(false)` 在 `reachable === wasReachable` 时直接返回不更新 banner — 这是另一个次要问题）
- **复现步骤**：
  1. 启动 sidecar（lock_busy=true 状态）
  2. 通过 Python requests 或大量并发请求访问 sidecar HTTP 端点
  3. 观察端口 3099 上 CloseWait 连接数量增加
  4. 后续请求全部超时
  5. 等待 60 秒后 CloseWait 连接数仅从 36 降至 27（自愈缓慢）
- **根因分析**：
  - sidecar 的 HTTP 服务器（axum/hyper）没有正确关闭客户端连接，导致连接停留在 CloseWait 状态
  - sidecar 没有连接超时清理机制，CloseWait 连接堆积导致新请求被拒绝
  - 这是 sidecar 后端的问题，不是前端交互的问题
- **恢复路径验证**：
  - 通过 Tauri invoke 调用 `stop_sidecar` + `start_sidecar` 成功重启 sidecar
  - 重启后所有端点恢复正常（/health 200, 3ms; 4 个信任中心端点全部正确响应）
  - monitor 状态恢复为 `isReachable=true, online=true, status="running", failCount=0`
  - banner 正确隐藏
- **影响评估**：
  - 用户在大量并发请求后可能遇到 sidecar"假死"
  - 前端 monitor 正确降级，但用户无法通过 UI 自动恢复（需要重启 sidecar）
  - 如果前端没有暴露"重启服务"入口（banner 没有正确显示），用户会困惑
- **修复建议**：
  1. **后端**：sidecar HTTP 服务器添加连接超时清理（如 30s 无活动关闭连接）
  2. **后端**：限制单客户端最大连接数，防止连接耗尽
  3. **前端**：banner 显示逻辑修复 — 当 monitor 检测到 sidecar 不可达时，强制显示 banner（即使 `_setReachable(false)` 状态未变）
  4. **前端**：banner 添加"重启服务"按钮，调用 invoke stop_sidecar + start_sidecar
- **全局影响**：本次审计通过 invoke 重启 sidecar 后，所有后续测试正常通过。该缺陷不影响 v0.8.22 修复点的正确性，但影响 sidecar 在高负载场景下的可用性。

### 6.2 P1 问题（本次审计新发现的次要问题）

#### IA-22-20：banner 显示逻辑在 sidecar 不可达时未正确显示

- **严重程度**：P1
- **现象**：当 sidecar 从可达变为不可达（CloseWait 堆积）时，monitor 正确降级为 `isReachable=false`，但 banner 仍然 `hidden=true`（不显示）
- **根因**：`_setReachable(reachable)` 在 `reachable === wasReachable` 时直接返回（[app.js:564](file:///g:/code-memory/static/app.js#L564)），不更新 banner。当 monitor 已经是 `isReachable=false` 时，再次 `_setReachable(false)` 不会显示 banner
- **影响**：用户在 sidecar 假死时看不到"服务未运行"提示，无法知道需要重启服务
- **修复建议**：`_setReachable` 在 `reachable=false` 时强制显示 banner（即使状态未变），或在 `check()` 失败达到阈值时主动调用 `_setReachable(false)` 并强制更新 banner

## 十、可注入的 InteractionGuard 断言逻辑（v0.8.22 回归增强版）

```javascript
/**
 * InteractionGuard v0.8.22-regression — 前端交互韧性守卫（回归增强版）
 *
 * v0.8.22 回归审计增强：
 *   - 修复 IA-22-19：sidecar 连接耗尽检测 + 自动重启提示
 *   - 修复 IA-22-20：banner 强制显示（即使 _setReachable 状态未变）
 *   - 验证 IA-01：daoAbortController 已挂载 window（运行时验证通过）
 *   - 验证 IA-02：注入 rejection 后 toast 显示（运行时验证通过）
 *   - 验证 IA-03：online getter 返回 boolean（运行时验证通过）
 */
const InteractionGuard = (function () {
  const MEMORY_WARN_THRESHOLD = 0.8;
  const MEMORY_CHECK_INTERVAL = 30000;
  const SIDECAR_HEALTH_FAIL_THRESHOLD = 3;
  const SIDECAR_RESTART_COOLDOWN = 30000; // 30s 重启冷却

  function init() {
    // 1. 全局错误处理（v0.8.22 IA-02 已修复，此处作为兜底）
    if (!window._lrcGlobalErrorRegistered) {
      window._lrcGlobalErrorRegistered = true;
      window.addEventListener('error', (event) => {
        console.error('[InteractionGuard] 全局错误:', event.error || event.message);
        try {
          if (typeof window.showToast === 'function') {
            window.showToast('发生未知错误，请刷新页面', 'error', 5000);
          }
        } catch (e) {
          console.error('[InteractionGuard] toast 显示失败:', e);
        }
      });
      window.addEventListener('unhandledrejection', (event) => {
        console.error('[InteractionGuard] 未捕获 Promise:', event.reason);
        try {
          if (typeof window.showToast === 'function') {
            const msg = (event.reason && event.reason.message) || '操作失败，请重试';
            window.showToast(msg, 'error', 3000);
          }
        } catch (e) {
          console.error('[InteractionGuard] toast 显示失败:', e);
        }
      });
    }

    // 2. 修复 IA-22-20：banner 强制显示钩子
    //    当 monitor._isReachable=false 但 banner.hidden=true 时，强制显示 banner
    if (window.sidecarHealthMonitor) {
      const origSetReachable = window.sidecarHealthMonitor._setReachable.bind(window.sidecarHealthMonitor);
      window.sidecarHealthMonitor._setReachable = function (reachable) {
        const wasReachable = this._isReachable;
        this._isReachable = reachable;
        if (reachable) {
          this._backoffStep = 0;
        }
        // 修复 IA-22-20：reachable=false 时强制显示 banner（即使状态未变）
        if (!reachable) {
          const banner = document.getElementById('sidecar-down-banner');
          if (banner) banner.hidden = false;
        }
        if (reachable === wasReachable) {
          // 状态未变，但仍需确保 banner 正确显示
          return;
        }
        // 调用原始 _setReachable 的后续逻辑（通过重新设置 _isReachable 触发）
        this._isReachable = wasReachable; // 恢复以便原始逻辑正确处理
        origSetReachable(reachable);
      };
    }

    // 3. 修复 IA-22-19：sidecar 连接耗尽检测 + 自动重启提示
    let lastRestartTime = 0;
    if (window.sidecarHealthMonitor) {
      const origCheck = window.sidecarHealthMonitor.check.bind(window.sidecarHealthMonitor);
      window.sidecarHealthMonitor.check = async function () {
        const result = await origCheck();
        // 检测连续失败达到阈值
        if (this._failCount >= SIDECAR_HEALTH_FAIL_THRESHOLD && !this._isReachable) {
          const now = Date.now();
          if (now - lastRestartTime > SIDECAR_RESTART_COOLDOWN) {
            lastRestartTime = now;
            console.warn('[InteractionGuard] 检测到 sidecar 连续失败 ' + this._failCount + ' 次，可能连接耗尽');
            try {
              if (typeof window.showToast === 'function') {
                window.showToast('LRC 服务无响应，正在尝试重启...', 'warning', 5000);
              }
            } catch (e) {}

            // 自动尝试重启 sidecar（通过 Tauri invoke）
            if (window.__TAURI_INTERNALS__ && window.__TAURI_INTERNALS__.invoke) {
              try {
                await window.__TAURI_INTERNALS__.invoke('stop_sidecar');
                await new Promise(r => setTimeout(r, 2000));
                await window.__TAURI_INTERNALS__.invoke('start_sidecar');
                console.log('[InteractionGuard] sidecar 自动重启成功');
                if (typeof window.showToast === 'function') {
                  window.showToast('LRC 服务已重启', 'success', 3000);
                }
                // 重启后强制 check
                await origCheck();
              } catch (e) {
                console.error('[InteractionGuard] sidecar 自动重启失败:', e);
                if (typeof window.showToast === 'function') {
                  window.showToast('LRC 服务重启失败，请手动重启应用', 'error', 5000);
                }
              }
            }
          }
        }
        return result;
      };
    }

    // 4. 内存监控（IA-22-08 沿用项）
    if (performance.memory) {
      setInterval(() => {
        const used = performance.memory.usedJSHeapSize;
        const limit = performance.memory.jsHeapSizeLimit;
        const ratio = used / limit;
        if (ratio > MEMORY_WARN_THRESHOLD) {
          console.warn('[InteractionGuard] 内存使用率 ' + Math.round(ratio * 100) + '%');
          if (typeof window.showToast === 'function' && !window._memWarnShown) {
            window._memWarnShown = true;
            try {
              window.showToast('内存使用过高，建议刷新页面', 'warning', 5000);
            } catch (e) {}
            setTimeout(() => (window._memWarnShown = false), 60000);
          }
        }
      }, MEMORY_CHECK_INTERVAL);
    }

    console.log('[InteractionGuard] 回归增强版已初始化（全局错误+banner强制+连接耗尽检测+内存监控）');
  }

  return { init };
})();

// 自动初始化
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', InteractionGuard.init);
} else {
  InteractionGuard.init();
}
```
