## 三、本次新增的 11 个问题评估

### 3.1 P0 问题（3 个）

#### P0-01：SPA 路由白屏

| 维度 | 评估 |
|------|------|
| **严重性** | 🔴 **P0 — 用户无法使用**：非 `/dashboard` 路径的 SPA 路由直接导航导致白屏（`chrome-error://chromewebdata/`），用户完全无法操作 |
| **根因** | 侧边栏服务端（`src/server.rs:3214-3292`）仅定义了 `/`、`/dashboard`、`/dashboard/` 路由，其他 SPA 路径（如 `/memory-search`、`/settings`、`/trust-center`）返回 404。Tauri WebView 加载 404 页面显示白屏 |
| **代码位置** | `src/server.rs:3227-3230` — 路由定义 |
| **修复方案** | 在 `src/server.rs` 的路由表中添加 catch-all 路由 `/*` 指向 `dashboard_handler`，实现 historyApiFallback 模式。注意：catch-all 必须位于所有 API 路由之后，避免拦截 API 请求 |
| **工作量** | ⭐ 小（1 文件，~5 行） |
| **风险** | 🟢 低 — catch-all 是标准 SPA 模式，axum 路由优先级确保精确匹配优先 |
| **不可修复说明** | 无。这是标准修复，不存在技术障碍 |

#### P0-02：Logo 图片 404

| 维度 | 评估 |
|------|------|
| **严重性** | 🔴 **P0 — 品牌形象破坏**：Logo 图片请求 404，无 alt 文字回退，favicon 缺失，侧边栏 Logo 显示破损图片 |
| **根因** | PNG Logo 文件存在于 `static/assets/logo/LRC桌面端Logo设计-26aa57e9-7935-4ece-badf-bd52dcccd343.png`，但侧边栏服务端的 `logo_asset_handler`（`src/server.rs:1842-1866`）仅处理 `.svg` 文件。HTML（`static/index.html:10,40`）引用了该 PNG 路径 |
| **代码位置** | `src/server.rs:1842-1866`（logo handler）+ `static/index.html:10,40`（HTML 引用） |
| **修复方案** | 方案 A（推荐）：将 HTML 中的 Logo 引用从 PNG 改为 SVG（`logo-horizontal.svg` 或 `logo-primary.svg`），因为 SVG 已在服务端正确处理。方案 B：在 `logo_asset_handler` 中添加 PNG 的 MIME 支持并 `include_str!` 嵌入 PNG 文件 |
| **工作量** | ⭐ 小（1-2 文件，~5 行） |
| **风险** | 🟢 低 — 纯静态资源路径调整 |
| **不可修复说明** | 无。方案 A 和 B 均可行，推荐方案 A 减少二进制体积 |

#### P0-03：testEmbedderConnection 超时无反馈

| 维度 | 评估 |
|------|------|
| **严重性** | 🔴 **P0 — 功能静默失败**：用户点击"测试链接"按钮后，若 `embedder-model` input 不存在则函数静默退出（`document.getElementById('embedder-model')?.value` 为 undefined，`!modelId` 检查通过但后续逻辑未执行）；超时仅在 console 报错，用户无感知 |
| **根因** | 双重问题：① `embedder-model` hidden input 在 settings 页面的 HTML 中不存在（见 IA-22-100）；② `testEmbedderConnection`（`app.js:7363-7407`）的 catch 块虽调用了 `showToast`，但超时场景下错误信息不够明确 |
| **代码位置** | `static/app.js:7363-7407`（`testEmbedderConnection`）+ `static/index.html`（settings 标签页） |
| **修复方案** | ① 在 settings 标签页 HTML 中添加 `<input id="embedder-model" type="hidden">`；② 在 `testEmbedderConnection` 的 catch 块中检测超时错误（`e.name === 'AbortError'`），显示"测试连接超时，请检查网络或镜像源"的 Toast |
| **工作量** | ⭐ 小（2 文件，~10 行） |
| **风险** | 🟢 低 — 纯前端修复 |
| **不可修复说明** | 无。这是标准的前端缺陷修复 |

| 维度 | 评估 |
|------|------|
| **严重性** | 🟡 **P1 — 用户体验混乱**：清除配置弹窗（如 LLM 配置弹窗）取消后，旧错误消息未清除，用户再次打开时看到残留错误 |

| **代码位置** | `static/app.js` — 模态框关闭处理函数 |
| **修复方案** | 在模态框关闭处理函数中，添加 `querySelectorAll('.error-message, .has-error')` 的清除逻辑，或调用现有的错误清除函数 |
| **工作量** | ⭐ 小（1 文件，~5 行） |
| **风险** | 🟢 低 |
| **不可修复说明** | 无 |

#### P1-02：全局按钮防抖缺失

| 维度 | 评估 |
|------|------|
| **严重性** | 🟡 **P1 — 潜在重复提交**：快速点击按钮（如"测试链接"、"下载并安装"、"应用"等）缺乏防抖机制，可能导致重复请求 |
| **根因** | 部分按钮已有防抖（如 `handleStartServiceClick` 有 `_startServiceInProgress` 守卫，`manualRefreshDashboard` 有 `_isManualRefreshing` 标志），但非所有按钮都覆盖 |
| **代码位置** | `static/app.js` — 多个按钮点击处理函数 |
| **修复方案** | 为所有异步操作按钮添加 `disabled` 状态管理（点击时禁用，完成后恢复）。可复用现有 `_inFlight` 模式或创建通用防抖工具函数 |
| **工作量** | ⭐⭐ 中（多个按钮处理函数，需逐一检查） |
| **风险** | 🟡 中 — 需要确保按钮状态正确恢复，避免永久禁用 |
| **不可修复说明** | 无。但需注意不要过度设计，优先覆盖用户高频操作的按钮 |

#### P1-03：搜索无加载指示器

| 维度 | 评估 |
|------|------|
| **严重性** | 🟡 **P1 — 用户不确定性**：记忆搜索过程中无 loading 状态，用户不知道搜索是否已触发 |
| **根因** | 代码审查发现 `searchMemories`（`app.js:5833-5841`）实际上已显示骨架屏（skeleton）。问题可能在于：① 防抖 300ms 期间无任何反馈；② 快速输入时骨架屏闪烁 |
| **代码位置** | `static/app.js:5797-5800`（`debouncedMemorySearch`）+ `static/app.js:5833-5841`（骨架屏渲染） |
| **修复方案** | 经静态代码审查，**该问题已部分修复**（骨架屏存在）。建议在防抖期间添加输入框下方的迷你加载指示器（如脉冲小点），表明搜索正在防抖等待中 |
| **工作量** | ⭐ 小（1 文件，~10 行） |
| **风险** | 🟢 低 |
| **不可修复说明** | 骨架屏已实现，属于增强型优化 |

#### P1-04：空配置时测试连接按钮未 disabled

| 维度 | 评估 |

| **工作量** | ⭐ 小（1 文件，~5 行） |
| **风险** | 🟢 低 |
| **不可修复说明** | 无 |

| 维度 | 评估 |
